# 墨迹互变：墨团与回声融入全站

状态：已决定，按场景分批实现。完成后仍有效的规则并入 `AGENTS.md`，本文件精简。

## 目标

墨团（主体）可分出回声；回声可变为任意元素（文字、图标、按钮），任意元素也可化回回声。墨团是主体，可离开首页介绍区附着到别处。读者可用鼠标做简单互动。只做桌面（≥900px 或按场景门槛、精细指针、未要求减少动态效果）；手机和减少动态效果保持静态或直接切换。

## 共用原语

1. **回声画在主体的 goo 组里**：回声是 `#fluid-ip-goo` 滤镜组内的路径，才能与主体、彼此融合（出芽有颈、分裂有缢缩）。屏幕坐标经 `svg.getScreenCTM().inverse()` 换成 SVG 坐标（已含 CSS 缩放）。滤镜区域随包围盒收紧，避免大区域卡顿尖峰。
2. **元素 ↔ 墨团**：给真实元素临时挂 SVG 滤镜（`feGaussianBlur` + alpha 阈值 `feColorMatrix`），单参数 m∈[0,1]：m=0 为同色墨团，m=1 为清晰原样。结束即移除 `filter` 与临时滤镜节点。
3. **交接不做透明度交叉淡化**：回声落地先舒展成目标墨带（尺寸取文本 Range 矩形并集），元素以 m=0 在其下方完全显形后回声再淡出，然后 m 0→1。
4. **单一时钟**：每个场景一条 rAF 时间轴 `render(t)`；收回即 t 从 1 走到 0。空闲无 rAF；中断（缩放、隐藏页面、历史导航、门槛失效）统一清理回声、滤镜和行内样式。
5. 共享代码放 `assets/js/fluid-ink.js`，挂 `window.FluidInk`（`blobPath` 等）；颜色只取主题变量或元素自身 `color`。

## 场景

- **A 入口转场**（`fluid-transition.js`）：进场约 2.2s、收回约 1.8s。主体挤压回弹并出芽 → 回声依次缢缩脱离 → 主体沿弧线移到介绍区并缩小；回声弧线飞行、按速度拉伸，落地舒展成标题、简介、社交栏（一团分成三个图标）、导航 logo、右下角两键（共用一颗，末段一分为二）的墨带，再按原语 3 交接。导航与文章卡片只淡入不位移。取代旧的 `.fluid-page-echo` span 方案。
- **B 墨水换色**：主题键点击后以 View Transition + `clip-path: path(blob)` 从按钮漫开约 800ms；期间屏蔽 `.theme-transition` 颜色过渡。不支持或减少动态效果时维持原切换。翻转逻辑与 PaperMod 一致（`data-theme` + `localStorage 'pref-theme'`）。
- **C 首页墨团鼠标物理**（`fluid-ip.js`）：按住拖动，墨团跟着指针走并被拉长；指针方向决定形变轴向，指针速度决定形变量，松手后在 140px 内回弹、超出则断开成回声、借用规格数组的形态停留后回融。拖动超过 6px 不算点击。弹簧静止即停 rAF。（当前实现与"靠近出芽、拉出墨颈"的原始设想仍有差距，见文末 C 阶段修正。）
- **D 阅读进度附着**：文章页（有 `.toc-progress`）滚过导航后，克隆的 `.fluid-mark` 挂在进度条尖端，进度条是它拖出的墨线；滚动速度决定前倾与眼神，静止弹簧回正后停 rAF，`pointer-events: none`。文末签名进入视口时它缩回条内，签名形象从墨池冒出一次（IntersectionObserver 加 class，无 JS 时静态）。
- **E 复制按钮墨变**：代码块按钮文本变化时用原语 2 墨化再转清晰（约 400ms），MutationObserver 监听，不改 PaperMod 复制逻辑。

### C 阶段拖拽手感修正（2026-09-29）

基线同上。只改 `assets/js/fluid-ip.js` 的 Scene C 与 `fluid-ip-check.mjs`，B、D、E 未动。

- **滤镜面**：`expandGoo` 每帧跟随墨团改写 `#fluid-ip-goo` 的 x/y/width/height，等于每帧重建整块 900×760 的滤镜表面并重跑模糊，是"不丝滑"的主因。改为一次性钉住一块固定的 `GOO_PULL`（覆盖可达范围），松手或中断后恢复原值。与 A 阶段"按 16 单位取整、少改滤镜表面"是同一条理由。
- **形变轴向**：原来用墨团相对身体中心的方向 `atan2(by-250, bx-256)`。曲线拖拽时该方向滞后，指针一停更是完全不等于手的走向，所以"方向不对"。改为跟随指针**自身**的运动方向；慢速拖拽保留上一轴向，不做阈值切换（阈值切换才是上一轮"抽搐"的来源）。
- **形变量**：不再取弹簧速度（弹簧在指针停下时会过冲、反号，形变跟着来回摆），改为指针的平滑速度，按 ~750ms 时间常数衰减，快速拖拽后墨团保持形变再缓慢回圆。
- **帧率无关**：位置弹簧改为定步长子步（120Hz 走两步而不是把步长算两遍，否则 k² 刚度直接发散）；角度、形变、速度读数都按实测帧间隔归一化。

### C 阶段抖动与旋转修正（2026-09-29，同轮后续）

用户实测反馈两条：慢速拖动时墨团剧烈抖动；正常拖动刚停下时墨团概率性原地转动。

- **抖动来自方向估计**：原来用**相邻两次 `pointermove` 的位移方向**当轴向。手颤在相邻事件间就能反向 180°，而角度每帧都朝这个噪声方向转 25%，实测每帧摆动可达 0.28 rad（16°）——这正是"剧烈抖动"。改为平滑**速度矢量**而不是角度：位移在一个 ~75ms 窗口内累加后除以窗口时长，得到两个分量再各自低通；方向只是这个矢量的 `atan2`，幅值就是速度。相邻事件里方向相反的手颤在窗口内互相抵消，噪声在取方向之前就没了。轴向另有 2 单位/帧的死区，窗口内没动就完全不更新。
- **原地转动来自波纹相位**：`blobPath` 的 phase 原来直接用 rAF 时间戳（`now / 600`），与手是否在动无关。指针停下后相位继续推进，不等宽波纹绕着一圈 0.13 的凸起整体旋转，看起来就是原地打转。改为相位由墨团本帧位移累加（`move / 260`，上限每帧 0.35 rad），手停相位停，回弹阶段也停。
- **停顿会污染后续读数**：窗口一直开着时，一次长停顿会让"位移 ÷ 时间"把停顿算进分母，重新动起来的第一帧速度被严重低估。窗口有位移就正常结算，整窗没位移就重开窗口。
- **松手回弹的帧链**：`pointerup` 里原来写的是 `else if (bumpRaf) window.requestAnimationFrame(bumpStep)`——`bumpRaf` 非 0 就再排一帧，可那个句柄已经在跑了，于是重排一帧、句柄丢失、链断，回弹动画停住且形变量冻在释放时的值。改为走 `ensureBump()`，由句柄本身决定是否要排新帧。
- **弹簧停止条件**：墨团回到体内就立刻 `return`，会把形变量冻在释放时的值（下一个拖拽从"已变形"开始）。改为只要形变还没归零就继续步进，停下时把位置精确落在身体中心。
- 新增检查：按住拖拽不会触发断开（断开会重置墨团，检查会把它误读成"拖拽冻结"）、指针反向时轴跟着转、慢速带手颤的拖拽轴向每帧变化 < 0.06 rad 且形变量变化 < 0.05、松手后形变单调回圆且墨团停留数帧、滤镜区域全程只改一次。

拖拽仍未按原文档"最近边缘出芽、拉出墨颈"实现，出芽方案已被否：现在是一颗脱离主体、经 goo 融合的墨团，`dist < BR*0.75` 且松手即隐藏，主体上没有颈。

### C 阶段边缘裁剪与回程修正（2026-09-29，同轮后续）

用户实测：向左半屏拖拽墨团直接消失，松手却能正常变出图案；图案回到主体时应该先化回墨团。

- **消失是滤镜区域裁掉的，不是没画**。用 headless Chrome 走 CDP 实测（见下表）确认：固定区域 `x = -760` 的左边界离主体中心只有 500 单位，而向左拖动时墨团的 `d` 起点很快到达 `-922`，整块墨在区域之外，滤镜就把它裁没了。固定矩形的左右不对称（左 500、右 2000）让这个问题只在左侧暴露；向上拖到屏幕外同样会裁，只是不容易注意到。
- 改为**按视口测量**：拖拽开始时把视口四角用 `getScreenCTM()` 换成 SVG 坐标，取包围盒外扩 40 单位（`BLUR_PAD`，留给模糊、波纹和拉伸），一次性钉住；同时把墨团**夹在同一个盒子里**（减去 `BUMP_R * (1 + STRETCH_MAX)`）。两者同源，就不会再出现"画得出来但被裁掉"。区域只在每次拖拽开始时量一次，长度拖拽期间不变，A 阶段"少改滤镜表面"的原则仍然成立。
- **回程先化形再飞**：图案化回墨团必须是**显示阶段的一部分**，不是飞行的一部分——原来 `formMix` 在飞行末段才归零，视觉上是把图案本身拖回主体。现在四段是「化出（0–0.20，约 0.5s）→ 停留（0.20–0.62，约 1.05s）→ 化回墨团（0.62–0.82，约 0.5s）→ 墨团飞回（0.82–1，约 0.45s）」，图案完全消失之前墨团一动不动。同时把墨团半径从 `size * (1 - formMix)` 改成不随 formMix 塌缩，否则图案中心会留一颗黑球。

CDP 实测（1440×900，DPR 1，`localhost:1313`）：

|---|---|---|---|
| 左 (−430px) | x −2288 … 1632 | −949 | 全程在区域内 |
| 右 (+430px) | 同上 | +1445 | 全程在区域内 |
| 上 (−260px) | 同上 | y −485 | 全程在区域内 |
| 下 (+300px) | 同上 | y +1096 | 全程在区域内 |

断开动画实测（`getBBox`，同一颗回声）：图案不透明度 0.001 → 1（约 0.5s 化出，墨团同时从 101 收到 81 变成图案的体积）→ 保持 1 约 1.05s，墨团始终 81 → 化回墨团（约 0.5s，墨团仍 81，即已经是完整墨团）→ 墨团开始缩小并飞回（81 → 61 → 消失）。图案消失前后墨团位置不动，回程只有墨团在动。

### C 阶段掉头修正（2026-09-30）

用户实测：来回方向相反拖动时，墨团每次都像「掉个头」，仿佛有头有尾；期望是一个没有固定形状、外表随拖动形变的球体。

- **掉头来自两处**。一是形变用「轴向角 + 速率逼近」表示：反向时目标角相差 π，最短路径必经四分之一圈，轴向带着拉长的墨团一起转身。二是 `blobPath` 的波纹用奇次谐波（3、5），轮廓不中心对称，轴向翻转时表面花纹跟着翻面，加重「有头有尾」的观感。
- **形变改为双角空间矢量**。沿 θ 拉长与沿 θ+π 拉长是同一个形状，轴向生活在半圈圆上：矢量幅值是形变量，方向是轴向的两倍。平滑这个矢量而不是逼近轴向角——反向拖动时目标矢量方向不变（θ→θ+π 映射到 2θ→2θ+2π，同一点），只在速度过零时幅值变小，墨团先回圆、再沿同一直线重新拉长，全程不旋转。90° 转向时矢量过零，同样是「回圆再拉长」，没有可见旋转。低于死区或松手后保持原方向、只衰减幅值（`DEFORM_RATE` 一个速率同时逼近方向与幅值，二者不会失调）。原 `ANGLE_RATE`、`wrapPi` 随之删除。
- **墨团波纹只用偶次谐波**（2、4）：轮廓中心对称，任何表面花纹都不标记头尾，轴向翻转半圈表面完全不变。回声动画与断开飞行的墨团保留奇次谐波——它们的轴向不中途翻转，抖动感是已确认的视觉基准。
- 新增检查（`fluid-ip-check.mjs` 8f）：同一直线来回拖动，轴向全程不偏离该直线（半圈空间倾角 < 0.6 rad）、反向过程中形变先回落后恢复、终点仍沿原直线拉伸。
- headless Chrome + CDP 实测（1440×900，`localhost:1313`，合成 PointerEvent）：右向拖动 angle=0.000、stretch=1.695；原路反向 16 帧采样 maxTilt=0.000、minStretch=1.647；终点 angle=-0.000、stretch=1.699。轴向全程钉在拖动直线上，无任何旋转。合成事件反向是瞬时高速，真实手部减速过零时回圆更明显。

### C 阶段图案中心黑点修正（2026-09-30）

用户实测：小墨团断开化为图案或文字后，中心有一个黑圆点遮挡。

- **黑点就是断开回声的墨团本身**。`doBreakOff` 让墨团在整个停留阶段保持 0.8 倍半径垫在图案下面；图案层画在 goo 组之上，但中间是镂空的（文字的 counter、星形的空隙），垫底墨团从镂空处透出来，就成了盖在图案中心的黑圆点。
- 上一轮「墨团半径不能乘 `(1 - formMix)`，否则图案中心留黑球」的判断有误：该耦合正是正确做法，点击动画一直是这么做的。修正为 `size = spec.radius * (1 - formMix) * (1 - ease(flyT) * 0.45)`：化出时墨团随图案浮现同步缩没；停留阶段墨团为零（`blobPath` 半径 < 0.1 返回空路径）；化回时随图案淡出同步长回，图案消失那一刻恰为完整墨团；随后只有墨团飞回主体。
- 检查新增（`fluid-ip-check.mjs` 8e 内）：图案不透明度为 1 的每一帧墨团路径必须为空；起飞那一刻墨团路径必须已存在。headless Chrome + CDP 实测（1440×900，50ms 采样 48 帧）：停留 21 帧墨团路径全空；全程墨团半径超出 `(1 - 不透明度)` 耦合的部分为 0.0 SVG 单位。

### C 阶段滤镜区域被上一场动画收回（2026-09-30）

用户实测：Ctrl+Shift+R 后拖墨团，第一次正常，第二次拖远就消失、只在主体周围那个方框里才看得见，第三次又正常。

- **不是没画，是区域被换回来了**。第二次拖拽开始时 `gooPinned` 仍为 true（上一次断开还在播），所以 `pinGoo()` 直接返回、沿用大区域；而上一次断开在自己结束时调用 `breakCleanup()` → `restoreGoo()`，把手还是按住的那次拖拽连同区域一起还原了。此后墨团既不被夹住也不被过滤区域覆盖，于是只能在默认那块小方框里出现。隔次复现正是因为只有「下一次拖拽」才会落在「上一次收尾」之后。
- 修法是给区域加归属判断：`restoreGoo()` 先过 `gooNeeded()`（仍有拖拽意图，或墨团尚未回到主体），不满足就不还。相应的，`bumpStep` 里点击场景接管的分支要先把这次拖拽（含 `deformX/deformY`）落回主体，否则既还不了区域，也会让下次拖拽从一个残留拉伸的墨团开始。
- 回归检查（`fluid-ip-check.mjs` 8h）：拉断后立刻开始第二次拖拽并一直拖动到上一次断开结束之后，全程区域不得消失、墨团不得离开区域；拖完放开并等待静止后，区域必须回到默认值（否则会一直占用整块视口的滤镜面）。headless Chrome 实测：三次连续拖拽期间区域宽度始终为 3851（视口尺寸），墨团离开主体时始终有绘制，全部结束后区域回到默认值 900。

### 入口转场「不丝滑」的排查（2026-09-30）

用 headless Chrome + CDP 逐帧采样与 trace 归因，结论必须诚实地说：**这台机器复现不出稳定卡顿**。

- 热态（同一页面第二次进场以后）：三种配置（1440×900、DPR2 的 1280×800、去掉全部墨化滤镜）帧间隔都是 p50 8ms / p95 9ms / max 17ms，超过 32ms 的帧为 0。
- 冷态（页面刚加载好就点、正是 Ctrl+Shift+R 之后的那一次）：能测到 7–12 帧超过 32ms，最长 109–169ms，最长的单个事件是 `RunTask`/`GPUTask`（光栅化），合计主线程约 400ms。同一配置冷启动重复跑会在 0 与 7 帧之间摆动，噪声很大。
- 一次误判值得记：最初把「第一个变体的首 RUN」当成基准，得出了「墨化滤镜是唯一卡顿源」（去掉后 >32ms 从 11 帧降到 0）。加了热身之后两者没有差别——那 11 帧是**新渲染进程的预热**，不是动画本身。以后这类 A/B 必须每个变体单独冷启动、或者先热身，不能靠同进程里的标签页顺序。
- 真正尝试过的优化：把六个目标元素的墨化更新排成粗粒度班次（按 `t` 量化、黄金比例错峰，避免依赖帧计数破坏「收回是进场倒放」），主线程确实降约 15%（FunctionCall 137→105ms、UpdateLayer 16→8ms），**但暖态帧率毫无差别**，而且六个元素的窗口几乎完全重叠，平均每帧仍有约 4 次重算——想压下去就得粗到肉眼可见的台阶。收益不成比例，已撤回，只在代码里留下结论与实测数字。
- 保留的唯一改动：`.fluid-composing` 期间给 `.fluid-ip-orb` 加 `will-change: transform`，让这段每帧改 matrix 且有 goo 滤镜的形象走独立合成；类在场景结束后摘除，不会留下常驻图层。视觉无变化，收益需在真机确认。

用户实测两条：墨团变图案、图案变墨团、墨团回去这些过程偏快；快速拖向一个方向后突然停手，墨团不恢复形变，而是顺着移动方向一直保持拉长。

**1. 断开动画节奏**：总时长 2500ms → **3600ms**，四拍重新分配——化出 0→0.20（0.72s）、停留至 0.58、化回 0.58→0.80（0.79s）、飞回 0.80→1.00（0.72s）。停留段最长（约 1.37s），图案能被看清；化出与化回各留 0.7s 以上，不再是闪现。

**2. 停手不恢复的根因**：平滑速度 `pullVX/pullVY` 只在 `pointermove` 里结算。手彻底停住后**不再有事件**，速度冻在最后一个值，`bumpStep` 每帧读到的都是它，形变便一直保持到松手为止。这不是拖拽中的手感的偏差，而是「没有事件 = 永远不更新」。

- 修法：帧循环里用**帧时钟**记录最后一次量到移动的时刻（`lastMoveAt`，只在 `move > 0` 的帧更新），超过一个空窗口（`IDLE_WINDOW = 150`ms）后每帧按 `IDLE_DECAY = 200`ms 半衰衰减，按钮仍按下也照衰减；一旦恢复移动立即重新计量。
- 半衰期明显短于松手后的 `SPEED_DECAY`（750ms）：**停住的手不是被放开的果冻，它只是静止了**，应当较快回圆；松手后的余韵才需要长尾。
- 顺带修掉一处**时钟混用**：原先 `bumpStep` 用 rAF 时间戳 `now` 减 `pointermove` 里记的 `performance.now()`。真实浏览器两者同源没有后果，但检查脚本的手驱时钟与原点是分开的，混用会让衰减在第一帧就生效。现在两处都只读帧时钟。

- headless Chrome + CDP 实测（1440×900，横向快速拖动 320px 后彻底停手，按钮保持按下）：停手瞬间 stretch=1.53，随后 100ms 采样一次 —— 1.68 / 1.70 / 1.65 / 1.48 / 1.34 / 1.24 / 1.17 / 1.12 / 1.08 / 1.06 / 1.04 / 1.03，约 1.2s 基本回圆，墨团全程仍停在指针位置。
- 断开节奏实测（单次干净拖动 + 松手）：图案完全显示后停留 1.54s → 化回完成 +2.12s → 墨团清空 +2.97s，加上化出的 0.72s，总时长约 3.7s，与 3600ms 的设计一致。
- 8b 检查从「松手后形变必须单调下降」改为「**开始下降后不得再回升**」：松手后目标值本身在缓慢衰减，形变向其追赶时允许一次极小的上升，这与旧的 oscillations 断言意图不同，旧写法会被这次修正后的正常行为判失败。
